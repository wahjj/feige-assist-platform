## 2. 产品目标

系统是一套供单个商家本地使用的电商管理后台。商家登录后统一管理商品、订单、客户、客服会话和售后审批，并可通过同步接口把已有系统或后续抖音商家系统中的数据录入本系统。

产品需要同时满足两类使用场景：

1. **日常管理**：搜索和维护商品、订单、客户资料，查看客户历史订单与客服会话。
2. **客服处理**：在统一聊天工作台查看 AI 回复、人工回复和会话状态，必要时接管会话，并在售后动作执行前完成审批。

首版不追求多商家 SaaS 能力，重点是把单商家的数据关系、页面流程、客服安全边界和本地交付做完整。

## 3. 用户与权限

### 3.1 商家管理员

首版只有一个商家管理员账号。管理员可以访问全部商品、订单、客户、客服、审批和设置功能。

### 3.2 消费者演示入口

本地提供一个独立的客户咨询演示页，供项目评审者模拟消费者发送消息，观察 AI 自动回复、转人工和后续人工处理。

### 3.3 外部商家系统

商家系统通过同步 API 推送商品、订单、客户和客服消息。接口使用独立 API Key，不共享管理员登录密码。

## 5. 技术架构

系统采用“Vue 单页前端 + FastAPI 后端”的模块化单体交付。FastAPI 提供管理员 API、客户咨询 API、同步 API 和内部业务服务，同时托管 Vue 构建后的静态文件；浏览器加载 Vue 应用后通过与 FastAPI 的同源 JSON API 交互。

```text
浏览器：Vue 3 单页应用
  |
  v
FastAPI JSON API
  +-- 管理员 API
  +-- 客户咨询 API
  +-- 同步 API
  |
  v
业务服务
  +-- 商品
  +-- 订单
  +-- 客户
  +-- 客服会话
  +-- AI 编排与策略
  +-- 售后审批
  +-- 同步与审计
  |
  +-- OpenAI 兼容模型接口
  |
  v
SQLite + 本地商品图片
Vue 构建产物由 FastAPI 作为静态文件托管
```

### 5.1 页面技术

- Vue 3 和 Vite 构建单页应用。
- 使用 JavaScript，不使用 TypeScript；不使用 Java。
- 使用 Vue Router 管理商品、订单、客户、客服工作台、售后审批和设置页面。
- 使用组合式 API 和局部组合函数管理页面状态，不额外引入不必要的状态框架。
- 使用浏览器原生 `fetch` 调用同源 API。
- 手写 CSS 完成布局、配色、表格、表单和响应式效果。
- 搜索和筛选项同步到 URL 查询参数，便于刷新后保持筛选条件。
- 前端做即时字段提示，服务端继续执行权威业务校验。
- FastAPI 无需单独 CORS 配置，因为生产运行中 Vue 和 API 使用同一来源。

### 5.2 前后端接口

- 管理员页面通过 `/api/v1/admin/*` 调用业务 API。
- 本地消费者咨询页通过 `/api/v1/chat/*` 调用客服 API。
- 外部商家通过 `/api/sync/v1/*` 推送业务数据。
- 管理员登录成功后使用 HttpOnly Cookie 保持会话。
- 前端从会话初始化接口取得 CSRF Token，写请求通过 `X-CSRF-Token` 请求头提交。
- 未登录或会话过期时，API 返回 `401`，Vue Router 跳转登录页。

### 5.3 本地启动

- 提供 `start.bat` 双击启动脚本。
- 首次运行检查 Python 环境并创建项目虚拟环境。
- 依赖缺失时安装项目依赖。
- 首次运行检查 Node.js 和 npm，安装 Vue 依赖并构建前端静态文件。
- 前端源码或依赖发生变化时重新构建；无需构建时直接复用已有构建产物。
- 初始化 SQLite 数据库。首次运行进入管理员初始化页，由使用者设置唯一的用户名和密码；之后进入正常登录页。
- 启动 FastAPI 后自动打开默认浏览器。
- 服务只绑定 `127.0.0.1`，不监听局域网或公网地址。
- 再次双击脚本时复用已有环境和数据。

### 5.4 本地数据

- SQLite 数据库保存在 `data/merchant.db`。
- 上传的商品图片保存在 `data/uploads/products/`。
- 本地配置和密钥不提交到 Git。
- 关闭浏览器不会丢失数据；重启系统后会话、订单、客户和设置仍然存在。

## 6. 后台页面结构

登录后的页面使用固定左侧导航：

1. 商品
2. 订单
3. 客户
4. 客服工作台
5. 售后审批
6. 设置

顶部显示当前商家名称、管理员账号和退出登录入口。

### 6.1 商品页面

商品列表支持按名称、分类、上下架状态和库存状态筛选。

每件商品一行，包含：

- 商品图片缩略图。
- 商品名称。
- 分类。
- 单价。
- 当前库存。
- 上下架状态。
- 更新时间。
- 编辑和归档操作。

商品编辑表单包含：

- 名称。
- 分类。
- 商品图片上传。
- 价格。
- 库存。
- 商品描述。
- 上下架状态。

价格必须大于或等于 0，库存必须是非负整数。归档商品不出现在新建订单的可选商品中，但历史订单仍保留其名称、价格和关联标识。

手工创建或修改订单商品明细时，系统立即预占相应库存；修改数量时只调整差额，取消订单时恢复预占库存。库存不足时拒绝手工添加或修改，并提示可售库存。同步接口推送历史订单时即使库存不足也允许录入，但在同步结果中标记库存短缺，避免因本地初始库存不完整而阻塞商家导入。

### 6.2 订单页面

订单列表支持按订单号、客户昵称、客户手机号、订单状态和日期筛选。

每张订单显示：

- 订单号。
- 客户。
- 商品数量。
- 订单金额。
- 订单状态。
- 下单时间。
- 物流状态。

订单状态限定为：

- 待付款。
- 待发货。
- 已发货。
- 已完成。
- 已取消。

订单详情包含：

- 客户信息。
- 收货人、手机号和地址。
- 支付金额。
- 物流公司和运单号。
- 多个订单商品明细。
- 状态变更记录。
- 关联客服会话。

创建订单时可以先选择或新建客户，并通过 Vue 表单动态添加多个商品明细。前端即时计算预览金额，提交后由服务端重新校验库存、价格和总额。

待付款和待发货订单可以修改收货人、联系电话、地址和商品明细；已发货后锁定收货信息与商品明细，只允许更新物流信息和后续状态；已完成和已取消订单不可编辑。

### 6.3 客户页面

客户列表支持按昵称、手机号和标签筛选。

客户列表和聊天工作台默认脱敏显示手机号。客户详情页可以查看完整手机号。

客户详情包含：

- 昵称。
- 手机号。
- 标签。
- 内部备注。
- 创建来源：手工创建、订单创建或接口同步。
- 订单总数。
- 累计消费。
- 历史订单列表。
- 客服会话列表。

客户备注和标签属于本地管理字段。接口同步更新客户基础资料时不得覆盖这些字段。

客户订单总数不包含已取消订单。累计消费只统计待发货、已发货和已完成订单的成交总额，待付款与已取消订单不计入。

### 6.4 客服工作台

工作台采用三栏布局：

- 左侧：待处理、AI 处理中、待人工和已结束的会话队列。
- 中间：完整聊天记录、AI/人工回复标识、消息时间和发送表单。
- 右侧：客户摘要、关联订单、物流状态和售后操作。

工作台操作：

- 查看 AI 自动回复与人工回复。
- 手工发送消息。
- 接管会话。
- 结束会话。
- 查看关联客户和订单。
- 为当前会话发起售后审批。
- 刷新消息。

工作台每 5 秒轮询当前会话的新消息，同时保留“刷新消息”按钮供管理员立即更新。管理员发送消息后只更新当前会话区域，不刷新整个后台页面。

管理员接管后：

- AI 不再自动回复该会话。
- 人工发送的消息标记为人工回复。
- 原有 AI 消息完整保留。
- 会话状态显示为人工处理中。

### 6.5 售后审批

售后审批列表显示待处理、已通过、已拒绝和失败记录。

审批详情展示：

- 消费者原始诉求。
- 关联聊天上下文。
- 客户和订单摘要。
- 物流状态。
- 动作类型：退款、补偿或补发。
- 建议金额。
- AI 生成理由和系统策略命中原因。
- 审批操作和备注。

退款、补偿和补发未审批前不得执行。首版审批通过后只调用模拟售后执行器并记录模拟结果，不进行真实资金操作。

### 6.6 设置页面

设置页面分为四部分：

1. 管理员账号：修改密码。
2. 大模型配置：服务地址、模型名称、API Key 和连接测试。
3. 同步接口：接口地址、密钥轮换、接口说明和最近同步日志。
4. 数据维护：下载备份、上传恢复和查看本地数据位置。

大模型 API Key 和同步 API Key 默认只显示掩码；新密钥只在生成时显示一次，之后不能从页面读取明文。

## 8. 同步接口

同步接口位于 `/api/sync/v1`，使用 JSON 请求和 `Authorization: Bearer <api-key>` 鉴权。

### 8.1 商品

`POST /api/sync/v1/products`

批量创建或更新商品。每条记录必须包含 `external_id` 和名称；价格、库存、分类、描述和上架状态按请求更新。

### 8.2 客户

`POST /api/sync/v1/customers`

批量创建或更新客户。本地标签和备注不被同步覆盖。

### 8.3 订单

`POST /api/sync/v1/orders`

批量创建或更新订单及商品明细。订单必须包含 `external_id`、客户信息和商品明细；缺少商品时创建待完善临时商品。

### 8.4 会话与消息

- `POST /api/sync/v1/conversations`：创建或更新会话。
- `POST /api/sync/v1/messages`：批量录入消费者消息。

外部会话 ID 和外部消息 ID 保证幂等。消费者消息进入系统后可以触发 AI 处理。

消息同步接口同步处理新消费者消息并返回 AI 处理结果；相同外部消息 ID 的重复请求返回第一次保存的消息，不重复调用模型。

### 8.5 响应语义

每次请求返回：

- 本次有效记录数。
- 成功数量。
- 失败数量。
- 每条记录的 `external_id`、处理结果和可选错误原因。

批次允许部分成功，但失败项必须明确返回原因。同一记录重复推送不会创建重复数据。

### 8.6 适配器边界

同步 API 将请求映射为内部导入命令，不直接写数据库表。未来接入抖音或商家自有系统时，可以新增适配器，将外部字段转换为同一内部命令。

## 9. 真实大模型接入

首版支持 OpenAI 兼容的 Chat Completions 接口。设置页保存：

- 服务地址。
- 模型名称。
- API Key。
- 请求超时。

保存前提供“测试连接”，调用模型返回固定短文本，确认地址、密钥和模型名称可用。

模型输入包括：

- 当前客户。
- 关联订单和商品明细。
- 物流信息。
- 最近会话消息。
- 可用业务工具说明。
- 自动回复和安全策略。

模型输出必须满足结构化 JSON 格式，包括意图、回复草案、所需业务查询、拟议售后动作和是否转人工。

模型没有直接执行数据库写入、退款、补偿或补发的权限。业务查询由工具网关完成，售后动作由策略和审批服务决定。模型输出不合法、超时或请求失败时，系统将会话转为待人工，不生成虚假订单或物流结果。

管理员尚未配置模型时，管理功能仍可使用；新的客服消息进入后直接标记为待人工，并在工作台提示“大模型尚未配置”。

## 10. 客服与审批流程

1. 消费者从本地咨询页或同步接口发送消息。
2. 系统写入消息并关联客户与可选订单。
3. AI 根据商品、订单、物流和历史消息生成结构化建议。
4. 普通查询由 AI 自动回复。
5. 退款、补偿和补发生成审批。
6. 争议、高风险、权限不足或模型失败转为待人工。
7. 管理员在工作台查看会话并可接管。
8. 管理员通过或拒绝审批。
9. 所有动作写入操作和审计记录。

## 11. 安全与隐私

- 后台只监听 `127.0.0.1`。
- 管理员密码、同步 API Key 和模型 API Key 不明文保存。
- 模型 API Key 使用本机密钥加密后存入 SQLite。
- 本机密钥自动生成并只保存在 `data/local_secret.key`，不写入源码或 Git。
- 管理员登录使用 HttpOnly、SameSite=Lax 的服务端会话 Cookie。
- 所有后台写 API 使用 CSRF Token 请求头。
- 手机号在列表、聊天和日志中脱敏。
- 页面不显示完整密钥和内部异常堆栈。
- 商品和客户使用归档，不物理删除已关联业务记录。
- 本地备份包含数据库、商品图片和本机密钥，下载前要求管理员重新输入密码；备份文件必须按敏感文件保管。
- 恢复备份前显示覆盖提示，确认后才替换本地数据。

## 12. 错误与失败处理

- 表单错误：页面保留原输入并显示对应字段错误。
- 未登录：跳转管理员登录页。
- 无权限或过期会话：返回登录页并提示重新登录。
- 订单状态非法：拒绝流转并显示当前允许的下一状态。
- 同步鉴权失败：返回 `401`，不记录完整 API Key。
- 同步单条数据错误：该条失败，其他有效记录继续处理。
- 模型连接失败：设置页显示可读错误；客服会话转人工。
- 模型输出格式错误：不自动回复，转人工。
- 图片类型或大小不合规：拒绝上传并显示原因。
- 数据恢复失败：保留原数据，不删除备份。

## 14. 验收标准

1. 在 Windows 上双击启动脚本可以打开本机首次初始化页或后续登录页。
2. 前端由 Vue 3 和 Vite 构建，FastAPI 托管构建产物。
3. 单管理员可以完成商品、订单、客户的搜索和编辑。

8. 退款、补偿和补发在审批前执行次数为零。
9. 设置页可以保存并测试真实 OpenAI 兼容模型连接。
10. 设置页可以轮换同步密钥并提供可调用接口。
11. 同步接口可以幂等录入商品、订单、客户、会话和消息。
12. 重启后本地数据、模型配置和同步密钥仍然可用。
13. 备份可以下载，恢复前有明确确认。
14. 自动化测试覆盖主要页面流程、安全边界和同步接口。
15. Vitest 组件测试、Vue 构建和 FastAPI 测试全部通过。
