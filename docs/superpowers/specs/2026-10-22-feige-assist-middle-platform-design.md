# 飞鸽只读 AI 辅助中台设计

## 1. 文档状态

- 日期：2026-10-22
- 项目类型：单服装商家本地模拟演示，后续可交付私有化部署
- 当前阶段：等待用户审阅设计文档
- 前端：Vue 3、Vite、JavaScript
- 后端：Python、FastAPI、SQLite
- 产品定位：抖店飞鸽原生接待为主，中台只读同步并提供 RAG AI 建议
- 关系说明：本文档取代旧版“可写商家管理后台”的产品范围；原商品、订单、客户和会话的只读镜像能力继续保留，原发送消息、接管会话、商品/订单编辑和售后审批能力删除

## 2. 产品目标

系统是一套飞鸽辅助中台。买家消息和店铺业务数据从抖店单向同步到中台，中台只读展示会话、商品、SKU、订单和客户档案，并根据当前对话和业务上下文生成 RAG AI 建议，供客服复制到飞鸽后人工审核发送。

中台不接管飞鸽会话路由，不调用飞鸽发送接口，不替代抖店或飞鸽后台，不修改抖店商品、订单和售后数据。

当前阶段不接入真实抖店开放平台。系统通过模拟 OAuth、Webhook 和商品/订单拉取适配器展示完整流程，同时保留真实平台适配器契约。

## 3. 产品价值

飞鸽原生已经提供当前买家的商品、订单、会话和客服绩效，因此中台不重复宣称这些原生能力，而是补足以下能力：

1. **服装知识库与 RAG 建议**：维护尺码、面料、养护、搭配、售后特殊规则和常见问答，根据当前对话召回并生成更专业的参考话术。
2. **统一客户档案**：汇总客户历史会话、历史订单、购买偏好、中台本地标签和跟进备注。
3. **跨业务检索**：检索会话、订单、商品、SKU、面料、尺码和问题类型。
4. **中台独有业务分析**：分析高频咨询、商品咨询分布、售后原因、知识命中、AI 建议生成/复制和同步质量。

面向商家的统一口径：

> 飞鸽工作台原生可以查看当前买家订单、商品基础信息，并自带客服接待绩效与会话统计。本中台不替换飞鸽能力，而是在此基础上提供自定义服装知识库、RAG 智能建议、完整客户档案和自定义业务分析。

## 4. 首版范围

### 4.1 包含

- Windows 本地双击启动。
- 单商家管理员登录。
- 独立完整中台页面。
- 飞鸽右侧窄屏 AI 面板的路由占位和“规划中”说明。
- 只读会话列表与聊天记录。
- 兼容买家消息和客服已发送消息。
- 商品档案与多 SKU 明细。
- 只读订单、物流和售后状态。
- 客户镜像档案、历史订单和历史会话。
- 客户本地标签与跟进备注。
- AI 知识库维护。
- 本地关键词/全文 RAG 召回。
- OpenAI 兼容真实大模型接入。
- 三条结构化 AI 回复建议。
- RAG 来源展示、敏感词风险检查和一键复制。
- 业务分析。
- 同步状态、授权状态和手动拉取入口。
- 模拟飞鸽 Webhook 事件页面。

- 真实抖店应用审核、OAuth 凭据和正式飞鸽消息推送。

- 中台接管、排队、分流、响铃、接待计时或客服绩效计算。
- 商品、价格、库存或订单写回抖店。
- 中台编辑或删除抖店同步数据。
- 退款、补偿或补发审批执行。
- 真实资金操作。
- 向量数据库和语义向量检索。
- 飞鸽右侧面板的实际嵌入功能。
- 多商家、多租户和组织计费。
- 公网生产部署、域名和 TLS；真实 Webhook 上线时另做部署。

## 5. 核心设计原则

1. **飞鸽是唯一接待入口。** 中台不参与会话路由和消息发送。
2. **抖店是业务权威源。** 商品、SKU、库存、订单、售后和价格均为只读镜像；存在延迟时以抖店为准。
3. **AI 只提供建议。** 模型输出不进入聊天记录，不自动发送，不能执行任何业务动作。
4. **复制不等于发送。** 客服复制话术后在飞鸽人工审核发送，中台只记录复制统计。
5. **RAG 可解释。** 每条建议附召回知识来源，无命中时明确提示。
6. **失败不影响飞鸽。** 中台停机或 AI 失败不阻断原生客服接待。
7. **平台能力位于适配器之后。** 模拟实现和真实抖店实现使用同一内部接口。

## 6. 系统架构

```text
抖店 / 飞鸽（当前为模拟源）
        |
        +-- OAuth / Token（模拟）
        +-- 飞鸽事件 Webhook（模拟事件）
        +-- 商品/订单查询与定时拉取（模拟适配器）
        |
        v
FastAPI Sync Service
        |
        +-- 验签、去重、归一化、幂等更新
        +-- 只读镜像数据库
        |
        v
Vue 3 辅助中台
        |
        +-- 会话中心
        +-- 商品 / 订单 / 客户查询
        +-- 知识库
        +-- AI 建议
        +-- 业务分析
        +-- 同步与设置
```

### 6.1 模块边界

- `integrations`：抖店 OAuth、Webhook、商品/订单拉取契约与模拟实现。
- `ingestion`：事件验签、去重、映射和同步。
- `catalog`：只读商品及 SKU 镜像。
- `orders`：只读订单及订单商品明细镜像。
- `customers`：客户镜像和本地标注。
- `conversations`：会话与消息只读镜像。
- `knowledge`：知识条目、产品绑定和本地检索。
- `assistant`：上下文组装、模型调用、建议校验和复制统计。
- `analytics`：中台独有业务分析。
- `demo_events`：管理员模拟飞鸽事件。
- `api`：管理员只读 API、模拟 Webhook 和设置接口。

## 7. 后台页面设计

登录后使用独立完整中台页面。

### 7.1 概览

- 今日同步消息数。
- 活跃会话数。
- 商品/SKU 数量。
- 订单数量与待关注订单。
- AI 模型连接状态。
- 最近一次商品、订单和会话同步时间。
- 最近同步失败或延迟提示。
- 高频咨询主题和建议复制趋势。

所有数字必须标识为镜像数据，不显示飞鸽原生客服绩效。

### 7.2 会话中心

会话中心采用三栏布局：

- 左侧：待接待、已接待、已关闭会话；状态来自飞鸽事件。
- 中间：只读聊天记录，区分买家消息、客服已发送消息、图片消息和未知角色。
- 右侧：三个页签：
  - AI 建议。
  - 订单与商品。
  - 客户资料。

页面禁止出现发送消息、回复买家、接管会话等操作。允许的操作只有：

- 手动刷新当前会话。
- 生成 AI 建议。
- 复制建议。
- 查看来源和订单商品详情。

会话完整性标记：

- `完整`：同时同步到买家与客服消息。
- `仅买家消息`：平台未提供客服外发消息。
- `同步中`：最近消息正在补拉。
- `同步异常`：保留旧消息并显示最后成功时间。

### 7.3 AI 建议区

- 显示当前对话使用的上下文摘要。
- 显示召回的知识条目和商品/SKU。
- 生成三条建议：专业说明、简洁直接、温和安抚。
- 新买家消息进入且模型已配置时，自动生成一次建议；页面保留“重新生成”按钮。
- 每条建议提供复制按钮和敏感词风险标记。
- 固定提示：“AI 建议仅供参考，请在飞鸽人工审核后发送。”
- 未配置模型时禁用生成并引导进入设置。
- 模型失败时显示可读错误，不生成占位假话术。

### 7.4 商品资料

只读列表与详情：

- 商品标题、主图、分类、状态、平台属性和商品知识绑定状态。
- 多个 SKU：颜色、尺码、规格、价格、库存、外部 SKU ID。
- 面料、尺码、养护和售后规则等知识关联。
- 搜索与筛选：商品名称、SKU、尺码、分类、库存状态。

不提供新增、编辑、下架或归档操作。

### 7.5 订单查询

只读查询：

- 按订单号、客户、商品、SKU、订单状态和日期筛选。
- 订单详情、买家信息、订单金额、物流、售后状态和商品明细。
- 关联会话入口。

页面固定显示“订单和物流状态以抖店后台为准”。不提供改状态、退款、补偿或补发操作。

### 7.6 客户档案

展示：

- 昵称、手机号、外部客户 ID。
- 全部历史订单和会话。
- 订单数、累计消费和最近购买时间。
- 中台标签与跟进备注。

客户基础资料只读。标签和备注允许编辑，并明确显示“仅中台可见，不回写抖店”。

### 7.7 AI 知识库

知识类型：

- 商品知识。
- 尺码表。
- 面料与养护。
- 搭配建议。
- 售后规则。
- 常见问答。
- 禁止话术或敏感说明。

知识条目字段：

- 标题。
- 类型。
- 关联商品或分类。
- 关键词。
- 正文。
- 启用状态。
- 更新时间。

管理员可新增、编辑、启用、停用和删除本地知识条目。知识库修改不涉及抖店。

### 7.8 业务分析

- 高频咨询主题。
- 商品和 SKU 咨询分布。
- 尺码、面料、物流、售后知识命中分布。
- 售后问题原因分布。
- AI 建议生成次数。
- AI 自动生成成功率和平均生成时间。
- AI 建议复制次数。
- 敏感词拦截次数。
- Webhook 失败、同步延迟和手动拉取次数。

所有报表基于中台镜像和 AI 记录，不声称替代飞鸽客服绩效。

### 7.9 同步与设置

- 抖店连接状态和模拟 OAuth 状态。
- 飞鸽 Webhook 地址、验签状态和最近事件。
- 手动拉取商品、订单和会话状态。
- 同步延迟、失败与重试。
- 打开“模拟飞鸽事件”工具。
- 配置 OpenAI 兼容模型地址、模型名称和 API Key。
- 模型连接测试。
- 同步日志和安全事件。
- 数据备份信息。

业务分析中的咨询主题由本地确定性分类器根据消息文本标记为尺码、面料、物流、价格、搭配、售后或其他，不依赖大模型结果，因此模型不可用时仍可统计入站咨询。

### 7.10 飞鸽侧栏占位

保留 `/panel` 路由，显示：

> 飞鸽右侧 AI 辅助面板规划中

不实现飞鸽嵌入脚本、侧栏 API、鉴权握手或实际侧栏交互。当前阶段只保留路由和视觉占位，避免未来改变中台信息架构。

## 8. 核心数据流

### 8.1 入站消息

1. 飞鸽产生买家消息，真实环境推送 Webhook；本地演示由模拟事件页面产生等价事件。
2. 中台校验签名、时间窗口和事件 ID。
3. 重复事件直接返回成功，不重复保存或分析。
4. 中台保存会话、消息和角色，更新最后消息时间。
5. 根据关联客户和订单加载商品、SKU 与知识上下文。
6. 如果模型已配置，中台在首次保存新买家消息后自动生成一次 AI 建议；失败时不影响消息保存，客服可以点击“重新生成”。
7. 建议展示后，客服复制并在飞鸽发送。

### 8.2 商品与订单

1. 抖店商品或订单变更优先通过事件推送。
2. 定时拉取作为兜底。
3. 中台按外部 ID 更新只读镜像。
4. 同步失败时保留上一份成功快照，并展示最后成功时间和错误状态。
5. 中台任何本地操作都不反向修改抖店。

### 8.3 AI 建议

1. 读取会话中已同步的消息。
2. 读取客户、订单、商品和 SKU 快照。
3. 基于当前问题、商品和问题类型召回最多 5 条本地知识。
4. 组合结构化模型输入。
5. 调用真实大模型。
6. 校验模型 JSON 输出。
7. 执行敏感词拦截。
8. 保存建议和来源，不写入消息表。
9. 客服复制时增加复制事件。

## 9. 平台接入契约

真实抖店 API 的具体字段、权限包名称和签名规则必须以商家最终审批通过的开放平台文档为准。当前实现通过适配器隔离这些差异。

### 9.1 外部事件入口

`POST /integrations/doudian/feige/events`

请求应包含：

- 平台事件 ID。
- 事件类型。
- 时间戳。
- 店铺 ID。
- 签名头。
- 会话、消息、订单或商品载荷。

处理结果：

- `accepted`：首次接收并处理。
- `duplicate`：重复事件。
- `invalid_signature`：验签失败。
- `processing_error`：记录失败，可由补偿任务重试。

### 9.2 OAuth 契约

- `GET /integrations/doudian/oauth/start`
- `GET /integrations/doudian/oauth/callback`

当前模拟实现可直接将状态标记为 `demo_connected`。真实实现负责授权码交换、Token 加密和刷新。

### 9.3 数据拉取契约

- 拉取商品和 SKU。
- 拉取订单和订单商品明细。
- 拉取订单物流与售后状态。
- 拉取会话状态或执行补偿同步。

模拟适配器从本地种子数据返回稳定结果；真实适配器未来用同一接口实现。

### 9.4 禁止能力

中台不实现以下接口或内部函数：

- 发送买家消息。
- 修改订单状态。
- 修改商品、SKU、价格或库存。
- 创建退款、补偿或补发。
- 接管飞鸽会话。

若真实适配器包提供相关接口，也不得注入中台服务层。

### 9.5 中台内部 API

管理员 API 至少包含：

- `GET /api/conversations`：只读会话列表。
- `GET /api/conversations/{id}`：只读会话、消息、客户、订单和商品上下文。
- `POST /api/conversations/{id}/suggestions`：自动或手动生成 AI 建议，只写建议记录。
- `POST /api/suggestions/{id}/copy`：记录复制事件，不发送消息。
- `GET /api/products` 和 `GET /api/products/{id}`：只读商品与 SKU。
- `GET /api/orders` 和 `GET /api/orders/{id}`：只读订单和物流。
- `GET /api/customers` 和 `GET /api/customers/{id}`：客户镜像、历史记录与本地标注。
- `PUT /api/customers/{id}/annotations`：只更新本地标签和备注。
- `GET/POST/PUT/DELETE /api/knowledge`：仅维护本地知识条目。
- `GET /api/analytics`：中台独有业务分析。
- `GET /api/integration/status`：OAuth、Webhook 和同步状态。
- `POST /api/integration/pull/products`：模拟或执行商品只读拉取。
- `POST /api/integration/pull/orders`：模拟或执行订单只读拉取。
- `POST /api/demo/events`：管理员生成模拟飞鸽事件。

外部数据资源不提供新增、修改、删除或发送接口。

- 商品或 SKU ID。
- 召回排序。

### 10.8 事件与同步

- Webhook 事件 ID。
- 事件类型。
- 载荷摘要。
- 验签结果。
- 处理状态和错误。
- 首次接收时间。

同步运行：

- 同步类型。
- 开始和结束时间。
- 成功数、失败数。
- 错误摘要。

## 11. 本地 RAG 策略

演示版不接入向量数据库。

### 11.1 召回范围

- 当前商品绑定的知识。
- 当前商品分类绑定的知识。
- 与当前问题关键词匹配的公共知识。
- 当前订单涉及商品的知识。

### 11.2 排序

1. 精确商品绑定优先。
2. 商品分类匹配其次。
3. 关键词命中数量和权重。
4. 标题命中高于正文命中。
5. 同分时取最近更新的启用知识。

每轮最多召回 5 条。无命中时向模型明确返回空知识列表，并在页面提示“未命中知识库”。

### 11.3 后续替换

检索实现通过 `KnowledgeRetriever` 接口隔离。未来可替换为向量检索，不影响会话页面、建议生成和模型接口。

## 12. 模型与建议输出

模型仅支持 OpenAI 兼容 Chat Completions 接口。只有一个运行模式：配置真实模型后调用模型。未配置时不允许生成模拟建议。

模型输入：

- 当前店铺和商品。
- 当前客户和订单快照。
- 买家消息和已同步客服消息。
- 命中的知识条目。
- 回复约束和违规词规则。

模型输出必须为可校验 JSON：

```json
{
  "suggestions": [
    {"style": "专业说明", "text": "..."},
    {"style": "简洁直接", "text": "..."},
    {"style": "温和安抚", "text": "..."}
  ],
  "warnings": []
}
```

服务端再次执行：

- JSON 结构校验。
- 建议条数校验。
- 长度限制。
- 敏感词检查。
- 禁止承诺自动退款、补偿或补发。
- 禁止声称已执行任何订单动作。

敏感词命中后的处理：

- 建议标记为高风险。
- 禁止一键复制。
- 页面展示命中类别，不展示识别规则全文。

## 13. 模拟飞鸽事件工具

管理员可打开“模拟飞鸽事件”页面，选择：

- 买家文字消息。
- 客服文字消息。
- 图片消息。
- 会话状态变化。
- 商品变更。
- 订单变更。

事件表单提交后通过模拟 Webhook 入口进入真实的中台处理流程，不直接写数据库，确保验签、去重、同步和建议生成链路的可验证性。

预置模拟场景：

1. 买家询问连衣裙尺码，附带订单商品。
2. 买家询问面料是否起球。
3. 买家询问物流延迟。
4. 买家要求退款，系统只提供人工处理建议。
5. 重复 Webhook 事件。
6. 无客服消息的“仅买家消息”会话。

## 14. 安全与风险控制

- 中台不包含任何发送消息能力。
- 所有出站到业务系统的 API 白名单只包含只读查询。
- Webhook 验签失败记录安全日志。
- OAuth Token 和模型 API Key 加密保存。
- 管理员使用 HttpOnly 服务端会话和 CSRF Token。
- 页面不显示完整密钥。
- 外部网页图片使用安全域名白名单或本地缓存，避免任意内容注入。
- 用户消息和商品文本按纯文本渲染，禁止执行 HTML。
- AI 建议不作为业务事实展示，必须附带人工审核提示。
- 全部 AI 建议、复制和同步事件可追溯。
- 本地备份包含数据库和密钥，必须按敏感文件保管。

## 15. 故障兜底

- 中台宕机：飞鸽不受影响，客服直接使用原生接待。
- Webhook 失败：记录失败，商品和订单可由手动或定时拉取补偿。
- 会话状态不一致：显示飞鸽最近同步状态和最后同步时间。
- AI 未配置：建议区禁用并提示配置。
- AI 超时或输出错误：显示失败，不显示半成品。
- 知识库为空：提示未命中，模型不得编造店铺政策。
- 同步数据过期：保留快照，显示最后成功时间。
- Token 失效：同步中心告警，停止使用过期授权发起新请求。

## 16. 测试策略

### 16.1 只读边界

- 外部商品、SKU、订单和消息不存在写 API。
- 页面不出现发送、接管、编辑商品或修改订单按钮。
- 代码层不存在发送飞鸽消息的适配器方法。

### 16.2 同步

- 模拟 Webhook 首次事件入库。
- 重复事件按事件 ID 去重。
- 验签失败被拒绝。
- 商品和 SKU 按外部 ID 幂等更新。
- 订单与订单明细按外部 ID 幂等更新。
- 客户镜像更新不覆盖本地标签和备注。
- 同步失败保留旧快照。

### 16.3 会话

- 买家消息和客服消息正确区分。
- 未知角色不误标为客服。
- 完整性状态正确显示。
- 中台无法写入消息镜像。

### 16.4 RAG 与模型

- 商品绑定知识优先召回。
- 分类和关键词召回正确。
- 最多返回 5 条来源。
- 未配置模型时生成请求被拒绝。
- 模型测试连接不暴露 API Key。
- 模型 JSON 无效时建议生成失败。
- 三条建议结构正确。
- 敏感词内容禁止复制。

### 16.5 分析

- 生成、复制和拦截事件计数准确。
- 高频主题和商品分布基于镜像数据。
- 不展示飞鸽原生客服绩效。

### 16.6 端到端

- 模拟买家事件 → 会话更新 → 生成建议 → 显示来源 → 复制。
- 模型已配置时，新买家消息自动生成一次建议；重新生成产生新建议记录。
- 模拟商品/订单变更 → 只读页面更新。
- 修改客户标签/备注 → 页面更新且无出站请求。
- 中台 AI 失败 → 会话记录保持可用。

## 17. 验收标准

1. 双击本地启动脚本可以打开 Vue 辅助中台。
2. 商品、订单和会话页面均为只读。
3. 中台界面与后端均不存在飞鸽消息发送入口。
4. 模拟买家事件进入会话中心，重复事件不会重复入库。
5. 商品包含 SKU、尺码、面料和库存信息。
6. 订单详情可关联商品、SKU 和会话。
7. 客户基础资料只读，本地标签和备注可编辑。
8. 知识库可以新增、编辑、停用并绑定商品。
9. 未配置模型时不会生成任何 AI 建议。
10. 配置真实模型后可以生成三条带来源的建议。
11. 建议可以复制，并产生复制分析事件。
12. 敏感词建议禁止复制。
13. 业务分析可以展示咨询、售后、AI 和同步指标。
14. `/panel` 只展示预留说明，没有侧栏功能。
15. 自动化测试覆盖只读边界、同步去重和 AI 建议安全。
